## 2. Patokan per langkah (dari bukti di atas)

| Langkah | Kisaran | Kekuatan |
|---|---|---|
| Tayangan → kunjungan profil | tidak ada data | tak terbaca |
| Kunjungan profil → klik bio | 1-4% (IG), 3-8% (TikTok) | lemah |
| Klik → halaman → daftar/mulai | 2-10% (SaaS gratis), app web tanpa daftar bisa lebih tinggi | sedang |
| Halaman toko → pasang | 17-18% (iOS edukasi); tayangan → pasang 0,6% | sedang |
| Tayangan → pengguna baru (ujung ke ujung) | 0,2-1,2% (Reddit 0,2%; TikTok 0,8-1,2%) | sedang, kasus tunggal |

Catatan:
- Angka ujung ke ujung dari pendiri cenderung bias ke yang berhasil. Anggap batas atas.
- Aplikasi Keepo itu web: tanpa pendaftaran, jadi "klik → pengguna baru" kemungkinan lebih tinggi dari SaaS. Ini asumsi; belum diukur.

## 4. Hitungan mundur: 300 baru/bulan

Asumsi (tandai: **belum diukur**):
- Tayangan → klik: 0,2% / 0,5% / 1% (pesimis/sedang/optimis).
- Klik → pengguna baru: 25% / 40% / 60%.
- Tayangan per posting akun kecil: 300 / 1.000 / 3.000.
- 1 posting ≈ 0,5 jam (kerja ringan, bahan sudah ada).

| | Pesimis | Sedang | Optimis |
|---|---|---|---|
| Tayangan → baru | 0,05% | 0,2% | 0,6% |
| Tayangan dibutuhkan | 600.000 | 150.000 | 50.000 |
| Klik dibutuhkan | 1.200 | 750 | 500 |
| Posting/bulan dibutuhkan | 2.000 | 150 | 17 |
| Posting/minggu | ±465 | ±35 | ±4 |
| Jam kerja/minggu | ±230 | ±17 | ±2-3 |
| Baru/bulan bila 3 jam/minggu (±24 posting) | ±4 | ±48 | ±430 (tak stabil) |

Bacaan:
- Dengan 3 jam/minggu, hasil realistis: **±50-100/bulan**, dengan lonjakan sesekali.
- 300/bulan butuh posting yang meledak, bukan kerja rutin.
- Target kerja: **100 baru/bulan** dari 1 saluran terbaik. Naik ke 300 setelah ada bukti.

Saluran paling layak untuk 2-4 jam/minggu (urut):
1. Komunitas/Reddit: 1-2 posting cerita per bulan. Ledakan terbesar per jam, risiko aturan promosi.
2. Threads + bio Instagram: murah, sudah ada. Konversi kecil tapi tabungan rutin.
3. Video TikTok: biaya per posting tertinggi. Hanya bila bahan siap pakai.
4. Halaman App Store (setelah rilis): pasif, tapi tayangan → pasang edukasi hanya 0,6%.

## 6. Hasil cek /hitung untuk 3 ref (#1451)

Intinya:
- Ketiga ref sudah tercatat per sumber, termasuk pengguna baru.
- Tidak perlu ubah kode aplikasi maupun server.
- Tidak ada deploy manual yang dibutuhkan.

Yang dicek:
- Aplikasi (`cloud.js`) membaca `?ref=` saat pertama kali dibuka.
- Ref disimpan sekali di perangkat, lalu dikirim ke /hitung tiap hari aktif.
- Server (`api/`) menyaring ref: huruf kecil, angka, `_` dan `-`, maks 20 karakter.
- Tanpa ref, sumber dicatat sebagai `langsung`.
- Tanpa ID, tanpa IP, tanpa data pribadi.

Kesimpulan:
- `rd-1`, `th-bio`, `tt-bio` lolos saringan apa adanya.
- Pengguna baru = baris dengan hari pertama sama dengan hari ini, dihitung per sumber.
- Hanya kunjungan pertama seumur perangkat yang menyimpan sumber.

Catatan batas:
- Orang yang sudah pernah buka Keepo tidak dihitung sebagai baru dari ref.
- Mode uji (`?test`, `?api`) dan bot tidak dicatat.
